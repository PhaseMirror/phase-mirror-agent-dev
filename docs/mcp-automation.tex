\# MCP automation

Status: workflow contract. Published anchor:
PhaseMirror/phase-mirror-agent-dev, branch \texttt{master}.

\hypertarget{triggers}{%
\subsection{Triggers}\label{triggers}}

\texttt{.github/workflows/evolution.yml} runs on push to
\texttt{master}, on a pull request targeting \texttt{master}, and on
manual dispatch. It does not target \texttt{main}. The tree's branch is
\texttt{master}.

\texttt{.github/workflows/mcp-automation.yml} runs only on
\texttt{workflow\_dispatch}.

\hypertarget{validation-gates}{%
\subsection{Validation gates}\label{validation-gates}}

\texttt{evolution.yml} is hermetic. It runs, in order:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \texttt{cargo\ check\ -\/-workspace}
\item
  \texttt{cargo\ test\ -\/-workspace}
\item
  \texttt{cargo\ build\ -p\ phase-mirror-mcp\ -\/-release}
\item
  \texttt{cargo\ test\ -p\ phase-mirror-mcp}
\end{enumerate}

There is no \texttt{-\/-check-model} flag. The MCP binary does not
accept one. There is no webhook, no \texttt{webhook.site} post, and no
simulated payload. A step that posts to an external host and ignores
failure is a simulation, and it is not in this workflow.

\hypertarget{dispatch-commands}{%
\subsection{Dispatch commands}\label{dispatch-commands}}

\texttt{mcp-automation.yml} accepts one input, \texttt{command}, as a
choice. The choices are \texttt{build}, \texttt{test},
\texttt{validate}, and \texttt{check-contract}.

\hypertarget{mcp-automation-workflow-setup}{%
\section{MCP automation workflow
setup}\label{mcp-automation-workflow-setup}}

This repository now includes GitHub Actions automation for the Rust
workspace and for the Phase Mirror MCP server.

\hypertarget{included-workflows}{%
\subsection{Included workflows}\label{included-workflows}}

\hypertarget{phase-mirror-ci-mcp-validation-.githubworkflowsevolution.yml}{%
\subsubsection{\texorpdfstring{1. Phase Mirror CI \& MCP validation
(\texttt{.github/workflows/evolution.yml})}{1. Phase Mirror CI \& MCP validation (.github/workflows/evolution.yml)}}\label{phase-mirror-ci-mcp-validation-.githubworkflowsevolution.yml}}

The primary continuous integration workflow gates all pushes and pull
requests against \texttt{master}: - \textbf{Triggers}: - \texttt{push}
to \texttt{master} - \texttt{pull\_request} targeting \texttt{master} -
Manual execution via \texttt{workflow\_dispatch} - \textbf{Validation
Gates}: - Full workspace syntax and type check:
\texttt{cargo\ check\ -\/-workspace} - Workspace test suite execution:
\texttt{cargo\ test\ -\/-workspace} (validates 187 tests, including
\texttt{lexlean-stratum} contractivity and stratification witness) -
Release build of MCP server:
\texttt{cargo\ build\ -p\ phase-mirror-mcp\ -\/-release} - MCP
integration test verification:
\texttt{cargo\ test\ -p\ phase-mirror-mcp} - \textbf{Architectural
Policy}: - Replaces legacy simulated webhook dispatches and mock
\texttt{-\/-check-model} invocations with concrete, hermetic on-tree
compilation and test execution (ADR-015, SPEC.md §34.0).

\hypertarget{phase-mirror-mcp-automation-.githubworkflowsmcp-automation.yml}{%
\subsubsection{\texorpdfstring{2. Phase Mirror MCP Automation
(\texttt{.github/workflows/mcp-automation.yml})}{2. Phase Mirror MCP Automation (.github/workflows/mcp-automation.yml)}}\label{phase-mirror-mcp-automation-.githubworkflowsmcp-automation.yml}}

On-demand operational automation for the Phase Mirror Model Context
Protocol server: - \textbf{Triggers}: - \texttt{workflow\_dispatch} with
parameter \texttt{command} - \textbf{Supported Commands}: -
\texttt{build}: Compiles \texttt{phase-mirror-mcp} in release mode. -
\texttt{test}: Executes the full 17-test MCP suite (\texttt{governance},
\texttt{prismpm\_actions}, \texttt{stability\_witness},
\texttt{runtime\_harness}, \texttt{stonehenge\_simulation}). -
\texttt{validate}: Runs full release build followed by MCP and
\texttt{lexlean-stratum} contractivity validation. -
\texttt{check-contract}: Runs MCP contract governance harness. - Custom
cargo subcommands passed to \texttt{phase-mirror-mcp}.
