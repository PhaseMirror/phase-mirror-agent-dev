\texttt{095fbf04c4529b2d7c06250205abca8b7d825015}

\hypertarget{what-the-tree-has}{%
\subsection{What the tree has}\label{what-the-tree-has}}

\texttt{phase-mirror-mcp/src/main.rs} handles \texttt{-\/-register-mcp}.
It writes \texttt{\textasciitilde{}/.lmstudio/mcp.json} with
\texttt{type:\ stdio}, \texttt{command} set to \texttt{current\_exe()},
\texttt{cwd} set to \texttt{current\_dir()},
\texttt{PHASE\_MIRROR\_ENV=dev}, and \texttt{tools:\ {[}"*"{]}}.

\texttt{mcp-contract.json} is at the repo root. The server loads it from
the process cwd and exits 1 if that fails.

\hypertarget{what-the-config-is}{%
\subsection{What the config is}\label{what-the-config-is}}

The pasted block is a local stdio client entry. A local IDE that can
execute that path can spawn the binary. A GitHub Copilot Cloud Agent
container cannot open \texttt{/media/citizen/…}. That partition is not
in the cloud workspace.

\texttt{tools:\ {[}"*"{]}} is a client allowlist, not an MCP protocol
field the server enforces. It tells the client to offer every tool the
server advertises, including the prismpm tools. Those still resolve only
when \texttt{PRISMPM\_BIN} matches a lock digest.

\hypertarget{what-is-not-closed}{%
\subsection{What is not closed}\label{what-is-not-closed}}

\texttt{.github/workflows/evolution.yml} and \texttt{mcp-automation.yml}
still contain
\texttt{\textless{}\textless{}\textless{}\textless{}\textless{}\textless{}\textless{}\ HEAD}
markers at this head. GitHub Actions will not parse them. The local
registration does not repair that.
